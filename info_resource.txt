# ArgoCD Resource Recommendations - Production Environment

## Executive Summary

Based on the current issue analysis where the ArgoCD Application Controller is experiencing frequent OOMKilled restarts due to insufficient memory allocation, this document provides comprehensive resource recommendations for optimal ArgoCD performance in a production environment managing 100+ applications.

## Current State Analysis

### Identified Issues
- **Application Controller**: Currently limited to 2GB memory, experiencing OOMKilled every few minutes
- **High Application Load**: Managing 100+ ArgoCD applications across multiple namespaces
- **Resource Contention**: Evidence of repo-server pods also experiencing liveness probe failures

### Impact
- Service interruptions due to controller restarts (45 restarts observed)
- Degraded sync performance
- Potential application drift during controller downtime

## Recommended Resource Configurations

### 1. Application Controller (Critical Priority)

#### Current Configuration
```yaml
controller:
  resources:
    requests:
      cpu: 2000m
      memory: 2000Mi
    limits:
      cpu: 2000m
      memory: 2000Mi
```

#### **Recommended Configuration**
```yaml
controller:
  resources:
    requests:
      cpu: 2000m
      memory: 6Gi          # Increased from 2Gi
    limits:
      cpu: 4000m           # Increased from 2 cores
      memory: 8Gi          # Increased from 2Gi
```

#### Justification
- **Memory**: 6-8GB recommended for 100+ applications (60-80MB per 100 applications)
- **CPU**: Additional CPU headroom for sync operations and health checks
- **Safety Margin**: 25% buffer above expected usage

### 2. Repository Server (High Priority)

#### Current Configuration
```yaml
repoServer:
  autoscaling:
    enabled: true
    minReplicas: 2
  resources:
    requests:
      cpu: 400m
      memory: 512Mi
    limits:
      cpu: 400m
      memory: 512Mi
```

#### **Recommended Configuration**
```yaml
repoServer:
  autoscaling:
    enabled: true
    minReplicas: 3           # Increased from 2
    maxReplicas: 5           # Add maximum scaling limit
  resources:
    requests:
      cpu: 500m             # Increased from 400m
      memory: 1Gi           # Increased from 512Mi
    limits:
      cpu: 1000m            # Increased from 400m
      memory: 1.5Gi         # Increased from 512Mi
```

#### Justification
- **Higher Throughput**: More replicas handle concurrent Git operations
- **Memory**: Additional memory for Git operations and manifest caching
- **CPU**: Better performance for Helm templating and Kustomize builds

## Advanced Configuration Recommendations

### 1. Controller Performance Tuning

Add these parameters to `argocd-cmd-params-cm`:

```yaml
configs:
  params:
    # Increase parallel processing
    controller.status.processors: "20"        # Default: 20
    controller.operation.processors: "10"     # Default: 10
    
    # Optimize caching
    controller.app.state.cache.expiration: "1h"
    controller.default.cache.expiration: "24h"
    
    # Reduce reconciliation frequency for stable apps
    timeout.reconciliation: "300s"            # Default: 180s
    timeout.reconciliation.jitter: "30s"
    
    # Enable server-side diff for better performance
    controller.diff.server.side: "true"
```

### 2. Application Sharding (Future Consideration)

For scaling beyond 150+ applications:

```yaml
controller:
  replicas: 2                    # Scale to multiple controllers
  env:
    - name: ARGOCD_CONTROLLER_REPLICAS
      value: "2"
    - name: ARGOCD_CONTROLLER_SHARDING_ALGORITHM
      value: "round-robin"
```

### 3. Repository Server Optimization

```yaml
configs:
  params:
    # Enable repository caching
    reposerver.parallelism.limit: "10"
    
    # Git optimization
    reposerver.git.retry.max: "3"
    reposerver.git.retry.base.backoff: "1s"
```

## Monitoring and Alerting

### Resource Monitoring
```bash
# Monitor controller memory usage
kubectl top pod argocd-application-controller-0 -n argocd

# Check for OOMKilled events
kubectl get events -n argocd --field-selector reason=OOMKilling

# Monitor repo-server performance
kubectl top pods -n argocd -l app.kubernetes.io/name=argocd-repo-server
```

### Recommended Alerts
1. **Memory usage > 80%** of limits
2. **CPU throttling** detection
3. **Pod restart count** > 5 in 1 hour
4. **Sync operation latency** > 60 seconds
